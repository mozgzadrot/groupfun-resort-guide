# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project shape

Static site, no framework, no bundler. Cloudflare Pages serves the repo root directly:

- **Build command**: empty
- **Output directory**: `/`
- **No `npm install` required** for the site itself

The only tooling is one Node script (`scripts/build-index.mjs`) that regenerates the resort manifest after editing a resort JSON.

## Architecture

Three layers:

1. **Shell** (`index.html`, `styles/*.css`) — ~20-line HTML shell with the sidebar mount, the main-content mount, and a hamburger button. CSS is split into `tokens.css` (vars + reset), `base.css` (layout + mobile), `sidebar.css`, `filters.css` (region hero + toolbar + pills), `card.css`, and `detail.css`.

2. **Data** (`data/`)
   - `data/regions.json` — array of regions: `{slug, name, flag, description, filter_pills[], hero_stats[], hero_copy{}}`.
   - `data/resorts/<id>.json` — one file per resort, complete record (`ratings`, `category_ratings`, `sentiment`, `contact`, `description`, `highlights`, `considerations`, `reviews[]`, `photos[]`, `card_gradient`, `detail_gradient`). Resorts are self-contained — the per-id gradient maps that used to live inside the render functions are folded into each JSON.
   - `data/index.json` — **autogenerated** card-sized manifest used by the region grid. Regenerate with `node scripts/build-index.mjs` after editing any resort.

3. **Client** (`js/*.js`, ES modules, no bundler)
   - `data.js` — `loadRegions()`, `loadManifest()`, `loadResort(id)` with promise-caching.
   - `router.js` — History API. `start()` intercepts clicks on `a[data-link]`; `popstate` re-renders. Path shapes: `/` → redirects to `/riviera-maya/`, `/<region>/` → region grid, `/<region>/<resort>/` → resort detail.
   - `sidebar.js` — `renderSidebar(root)` iterates `regions.json` + manifest; `highlightActive(path)` sets `.active` from `location.pathname`.
   - `region-view.js` — renders hero + filter pills + toolbar + grid of `.resort-card` anchors with `data-*` attributes used by `filters.js`.
   - `resort-view.js` — composes the detail page from `hero`, `overview`, `categoryScores`, `highlights`, `photoGallery`, `reviews`, `quickFacts`, `sentimentPanel`, `contact` (all pure functions returning HTML strings).
   - `filters.js` — pure DOM operation on already-rendered cards. Reads `data-tags`, `data-name`, `data-tagline`, `data-location`, `data-rank`, `data-price`, `data-rating`, `data-sentiment` to show/hide and reorder. No re-render, no fetch.
   - `format.js` — `escapeHtml`, `stars`, `sentimentChip`, contact icon/label tables, rating-source labels.
   - `main.js` — entry: wires hamburger, calls `renderSidebar`, then `router.start()`.

## Routing & Cloudflare Pages

`_redirects` rewrites every unknown path to `/index.html` with status `200` (rewrite, not redirect) so deep links like `/riviera-maya/desire-pearl/` load the shell with the URL bar intact, and the client router reads `location.pathname`. Static asset prefixes (`/data/*`, `/styles/*`, `/js/*`) are exempted so the rewrite catch-all doesn't intercept them.

Locally, `python3 -m http.server 8080` works for the grid and detail pages, but **will 404 on a hard refresh of a deep link** because it doesn't honor `_redirects`. Use `npx wrangler pages dev .` to simulate Cloudflare Pages behavior including the rewrite.

## Common tasks

- **Add a resort**: create `data/resorts/<id>.json` (copy an existing file's shape), then run `node scripts/build-index.mjs`. The sidebar and the matching region grid pick it up automatically.
- **Add a region**: append an entry to `data/regions.json` with `{slug, name, flag, description, filter_pills, hero_stats, hero_copy}`. If the slug needs a country flag in the sidebar, add it to the `FLAG_ISO` map in `js/sidebar.js`.
- **Change the visual design**: edit the matching `styles/*.css` file. CSS variables live in `styles/tokens.css`.
- **Add a backend endpoint**: drop a file under `functions/api/<name>.js` — Cloudflare Pages auto-wires it. (Not used today.)

## Notes

- `_legacy/index.html` is the original monolith, kept temporarily for visual diff during the migration. Safe to delete once parity is confirmed in a browser. `scripts/extract-data.mjs` was the one-time extraction; safe to delete with `_legacy/`.
- All HTML strings rendered into the DOM pass user-facing fields through `escapeHtml` from `js/format.js`. New renderers should do the same.
- The sidebar's `.region-btn` and `.resort-link` were originally `<button>`s with `onclick` handlers; they're now `<a href data-link>` anchors. The router intercepts the click so SPA navigation still happens, but right-click "Open in new tab" works and middle-click works.
